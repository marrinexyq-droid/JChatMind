# 03 — 工具系统（Tool Framework）

> 相关包：`com.kama.jchatmind.agent.tools`
> 设计目标：可扩展、可治理、FIXED/OPTIONAL 双模式

---

## 一、整体架构

```
Tool 接口 (agent/tools/Tool.java)
  ├─ getName()        → 工具唯一标识
  ├─ getDescription() → LLM 理解用的描述
  └─ getType()        → FIXED / OPTIONAL
       │
       ▼
ToolType 枚举 (agent/tools/ToolType.java)
  ├─ FIXED    → 所有 Agent 强制拥有（如 KnowledgeTool, TerminateTool）
  └─ OPTIONAL → 按 Agent 配置选择（如 DataBaseTool, EmailTool）
       │
       ▼
工具实现类 (@Component 自动注册)
  ├─ FIXED:
  │   ├─ KnowledgeTools  → RAG 知识库检索
  │   ├─ TerminateTool   → 终止 Agent 循环
  │   └─ DirectAnswerTool(已禁用@Component)
  │
  └─ OPTIONAL:
      ├─ DataBaseTools   → PostgreSQL 查询
      ├─ EmailTools      → QQ 邮件发送
      └─ FileSystemTools(已禁用@Component)
       │
       ▼
ToolFacadeServiceImpl (收集+分类)
  ├─ getAllTools()      → 全部工具
  ├─ getFixedTools()    → 按 FIXED 过滤
  └─ getOptionalTools() → 按 OPTIONAL 过滤
       │
       ▼
JChatMindFactory.resolveRuntimeTools()
  ├─ 固定工具（全部加入）
  ├─ 可选工具（只加入 Agent 配置中选择的）
  └─ buildToolCallbacks() → 转成 Spring AI 的 ToolCallback
       │
       ▼
JChatMind.think() → 以 ToolCallback[] 传入 chatClient
```

---

## 二、核心接口与枚举

### Tool.java

```java
public interface Tool {
    String getName();          // 工具名称（唯一标识，如 "KnowledgeTool"）
    String getDescription();   // 工具描述（LLM 理解用途）
    ToolType getType();        // FIXED（强制）或 OPTIONAL（可选）
}
```

### ToolType.java

```java
public enum ToolType {
    FIXED,     // 固定工具：所有 Agent 都拥有，不可移除
    OPTIONAL   // 可选工具：按 Agent 配置选择是否启用
}
```

## 三、各工具详解

### 3.1 KnowledgeTools.java — RAG 知识库检索（FIXED）

```java
@Component
public class KnowledgeTools implements Tool {

    private final RagService ragService;

    @Override
    public String getName() { return "KnowledgeTool"; }

    @Override
    public String getDescription() {
        return "用于从知识库执行语义检索（RAG）。输入知识库 ID 和查询文本，返回与查询最相关的内容片段。";
    }

    @Override
    public ToolType getType() { return ToolType.FIXED; }

    @Tool(name = "KnowledgeTool",
          description = "从指定知识库中执行相似性检索（RAG）。参数为知识库 ID（kbsId）和查询文本（query），返回与查询最相关的知识片段。")
    public String knowledgeQuery(String kbsId, String query) {
        List<String> strings = ragService.similaritySearch(kbsId, query);
        return String.join("\n", strings);
    }
}
```

- `@Tool` 注解来自 `org.springframework.ai.tool.annotation.Tool`
- Spring AI 通过 `MethodToolCallbackProvider` 扫描这个注解，自动生成 `ToolCallback`
- `name` 和 `description` 会被 LLM 看到，用来决定是否调用

### 3.2 TerminateTool.java — 终止信号（FIXED）

```java
@Component
public class TerminateTool implements Tool {

    @Override
    public String getName() { return "terminate"; }

    @Override
    public String getDescription() { return "跳出 Agent Loop 的工具"; }

    @Override
    public ToolType getType() { return ToolType.FIXED; }

    @Tool(name = "terminate",
          description = "如果你觉得当前所有的任务已经执行完毕了，就执行这个工具调用")
    public void terminate() {}
}
```

**关键设计**：`terminate()` 是 **void 返回**。但它不是靠返回值来结束 Agent 的，而是靠 `execute()` 方法中检查调用的工具名：

```java
// JChatMind.execute() 第304-309行
if (toolResponseMessage.getResponses().stream()
        .anyMatch(resp -> resp.name().equals("terminate"))) {
    this.agentState = AgentState.FINISHED;
}
```

**工作原理**：
1. LLM 认为任务完成了 → 调用 `terminate` 工具
2. `toolCallingManager` 执行 `terminate()`（空方法）
3. `ToolResponseMessage` 里有一项 `name="terminate"`
4. `execute()` 检测到 → 设置 FINISHED 状态
5. 下一轮循环检查 `agentState != FINISHED` → 退出

### 3.3 DataBaseTools.java — 数据库查询（OPTIONAL）

```java
@Component
public class DataBaseTools implements Tool {

    private final JdbcTemplate jdbcTemplate;

    @Tool(name = "databaseQuery",
          description = "用于在 PostgreSQL 中执行只读查询（SELECT）...")
    public String query(String sql) {
        // 安全检查：只允许 SELECT
        String trimmedSql = sql.trim().toUpperCase();
        if (!trimmedSql.startsWith("SELECT")) {
            return "错误：仅支持 SELECT 查询语句";
        }

        // 执行查询 → 格式化结果（表格形式）
        List<String> rows = jdbcTemplate.query(sql, (ResultSet rs) -> {
            // 获取列名 → 计算列宽 → 收集数据 → 格式化表格
        });
        return "查询结果:\n" + String.join("\n", rows);
    }
}
```

**面试重点**：
- 只允许 SELECT 语句（安全问题）
- 用 `JdbcTemplate` 直接执行 SQL（注意：有 SQL 注入风险！因为只检查了 SELECT 前缀，没有做参数化）
- 返回格式化的表格字符串（列名 | 分隔线 | 数据行）

### 3.4 EmailTools.java — 邮件发送（OPTIONAL）

```java
@Component
public class EmailTools implements Tool {

    private final EmailService emailService;

    @Tool(name = "sendEmail",
          description = "发送邮件到指定的收件人...")
    public String sendEmail(String to, String subject, String content) {
        // 参数验证（非空校验 + 邮箱格式校验）
        if (!to.contains("@")) {
            return "错误：收件人邮箱地址格式不正确";
        }
        // 异步发送
        emailService.sendEmailAsync(to.trim(), subject.trim(), content.trim());
        return String.format("邮件已提交发送！\n收件人: %s\n主题: %s", to, subject);
    }
}
```

**`EmailServiceImpl.sendEmailAsync`**：
```java
@Async   // ← 也是异步的！

    SimpleMailMessage message = new SimpleMailMessage();
    message.setTo(to);
    message.setSubject(subject);
    message.setText(content);
    message.setFrom(from);

```

注意：这里的 `@Async` 和 Agent 的 `@Async` 用的是同一个线程池（AsyncConfig）。

### 3.5 FileSystemTools.java — 文件系统（已禁用）

```java
// @Component  ← 被注释掉了，不在 Spring 容器中
public class FileSystemTools implements Tool {

    private static final String BASE_DIRECTORY = System.getProperty("user.dir");

    // 提供方法：readFile, writeFile, appendToFile, listFiles, deleteFile, createDirectory

    // ⭐ 安全设计：路径遍历防护
    private Path validateAndResolvePath(String filePath) {
        Path basePath = Paths.get(BASE_DIRECTORY).toAbsolutePath().normalize();
        Path resolvedPath = basePath.resolve(filePath).toAbsolutePath().normalize();

        // 检查解析后的路径是否在基础目录内
        if (!resolvedPath.startsWith(basePath)) {
            throw new SecurityException("路径遍历攻击被阻止: " + filePath);
        }
        return resolvedPath;
    }
}
```

**为什么禁用？** 文件系统操作风险太高，Agent 可能被诱导执行危险操作（删除文件、写入恶意内容）。

## 四、工具收集与注册流程

### 4.1 ToolFacadeServiceImpl.java

```java
@Service
@AllArgsConstructor
public class ToolFacadeServiceImpl implements ToolFacadeService {

    // Spring 会自动把容器中所有 Tool 类型的 Bean 注入到这个 List
    private final List<Tool> tools;   // 当前有：KnowledgeTools, TerminateTool,
                                      //        DataBaseTools, EmailTools
                                      //       (FileSystemTools和DirectAnswerTool被禁用)

    public List<Tool> getAllTools() {
        return tools;  // 返回全部
    }

    public List<Tool> getOptionalTools() {
        return tools.stream()
                .filter(tool -> tool.getType().equals(ToolType.OPTIONAL))
                .toList();
    }

    public List<Tool> getFixedTools() {
        return tools.stream()
                .filter(tool -> tool.getType().equals(ToolType.FIXED))
                .toList();
    }
}
```

### 4.2 JChatMindFactory 中的工具解析

```java
private List<Tool> resolveRuntimeTools(AgentDTO agentConfig) {
    // 1. 固定工具：全部加入（系统强制）
    List<Tool> runtimeTools = new ArrayList<>(toolFacadeService.getFixedTools());

    // 2. 可选工具：只加入 Agent 配置中选择的
    List<String> allowedToolNames = agentConfig.getAllowedTools();
    //                                ↑ 从数据库取出，如 ["databaseTool", "emailTool"]

    Map<String, Tool> optionalToolMap = toolFacadeService.getOptionalTools()
            .stream()
            .collect(Collectors.toMap(Tool::getName, Function.identity()));

    for (String toolName : allowedToolNames) {
        Tool tool = optionalToolMap.get(toolName);
        if (tool != null) {
            runtimeTools.add(tool);
        }
    }
    return runtimeTools;
}

private List<ToolCallback> buildToolCallbacks(List<Tool> runtimeTools) {
    List<ToolCallback> callbacks = new ArrayList<>();
    for (Tool tool : runtimeTools) {
        // 用 Spring AI 的 MethodToolCallbackProvider 扫描 @Tool 注解
        ToolCallback[] toolCallbacks = MethodToolCallbackProvider.builder()
                .toolObjects(tool)  // ← 传入 Tool 实例
                .build()
                .getToolCallbacks();
        callbacks.addAll(Arrays.asList(toolCallbacks));
    }
    return callbacks;
}
```

**`MethodToolCallbackProvider` 的作用**：
- 扫描对象中所有 `@Tool` 注解的方法
- 提取 `name` 和 `description`
- 生成 `ToolCallback`（包含工具名称、描述、参数 schema、执行逻辑）
- 最终的 `ToolCallback[]` 传给 `chatClient` 的 `.toolCallbacks()`

## 六、新增一个工具的完整步骤

假设要新增一个"计算器工具"：

```java
// 1. 新建类，实现 Tool 接口 + @Component
@Component
public class CalculatorTools implements Tool {

    @Override
    public String getName() { return "calculatorTool"; }

    @Override
    public String getDescription() { return "一个用于执行数学计算的工具"; }

    @Override
    public ToolType getType() { return ToolType.OPTIONAL; }

    @Tool(name = "calculator", description = "执行数学计算，参数：expression - 数学表达式")
    public String calculate(String expression) {
        // 计算逻辑
        return "结果: " + eval(expression);
    }
}
```

**需要改的代码**：只有这一个文件。
**不需要改的代码**：`JChatMind.java`, `JChatMindFactory.java`, `ToolFacadeService.java`, Controller, 前端等全部 0 修改。

**为什么？**
- `@Component` → Spring 自动扫描注册到容器
- `ToolFacadeServiceImpl` 通过 `List<Tool>` 自动收集
- `JChatMindFactory` 通过 `ToolFacadeService.getOptionalTools()` 自动获取
- 前端通过 `GET /api/tools` 自动展示

这就是"可扩展框架"的含义。

## 七、面试核心问题

### Q1: FIXED 和 OPTIONAL 的区别在代码中如何实现？

`ToolFacadeServiceImpl` 通过 `tool.getType().equals(ToolType.XXX)` 过滤。
`JChatMindFactory.resolveRuntimeTools()` 中 FIXED 全部加入，OPTIONAL 只加入配置选中的。

### Q2: 新增工具需要改哪些代码？

只需要新建一个类实现 `Tool` 接口，加上 `@Component` 和 `@Tool` 注解。**0 行核心代码修改**。

### Q3: TerminateTool 是怎么让 Agent 结束的？

`execute()` 方法中检查 `ToolResponseMessage` 里的工具名，如果包含 `"terminate"`，设置 `agentState = FINISHED`。

### Q4: DataBaseTools 有什么安全问题？

只检查了 SQL 是否以 `SELECT` 开头，但 `SELECT 1; DROP TABLE users;` 这种拼接语句也可能通过检查。更好的做法是用 `JdbcTemplate` 的参数化查询或增加更严格的 SQL 校验。

### Q5: 为什么 FileSystemTools 和 DirectAnswerTool 被禁用？

文件系统风险太高；DirectAnswer 被判定为多余（LLM 可以直接返回文本）。
