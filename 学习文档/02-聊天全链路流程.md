# 02 — 聊天全链路流程（请求从进入到响应的完整路径）

> 理解这条链路 = 理解了整个项目 80% 的架构

---

## 一、总览图

```
  前端                         后端
   │                           │
   │  POST /api/chat-messages   │
   │──────────────────────────►│  ChatMessageController
   │                           │  │
   │                           │  ▼
   │                           │  ChatMessageFacadeServiceImpl
   │                           │  │
   │                           │  ├─ 1. doCreateChatMessage()
   │                           │  │   └─ chatMessageMapper.insert()  ← 存UserMessage到DB
   │                           │  │
   │                           │  └─ 2. publisher.publishEvent(ChatEvent)
   │                           │       └─ @Async ChatEventListener
   │                           │            └─ JChatMindFactory.create()
   │  ◄────── 200 OK ────────│                        │
   │                           │                        ▼
   │                           │                   JChatMind.run()
   │                           │                   ┌─ think()
   │                           │                   │   ├─ saveMessage()→DB
   │  ◄──── SSE: AI_THINKING ──│──── (可选) ───────│   └─ refreshPendingMessages()→SSE
   │                           │                   ├─ execute()
   │                           │                   │   ├─ saveMessage()→DB
   │  ◄─── SSE: AI_EXECUTING ──│──── (可选) ───────│   └─ refreshPendingMessages()→SSE
   │                           │                   └─ ... 循环直到FINISHED
   │  ◄── SSE: AI_DONE ───────│──────────────────────┘
```

## 二、分步详解

### 第1步：前端发送消息

前端 `AgentChatView.tsx` 的 `handleSendMessage()`：

```
1. 如果 chatSessionId 不存在：
   a. POST /api/chat-sessions → 创建新会话
   b. POST /api/chat-messages → 发送第一条消息
   c. navigate(`/chat/${newSessionId}`) → 跳转到新会话
   d. React useEffect → 建立 SSE 连接

2. 如果 chatSessionId 存在：
   a. POST /api/chat-messages → 发送消息
   b. getChatMessages() → 刷新消息列表
```

### 第2步：Controller 接收（ChatMessageController.java）

```java
@PostMapping("/chat-messages")
public ApiResponse<CreateChatMessageResponse> createChatMessage(
        @RequestBody CreateChatMessageRequest request) {
    return ApiResponse.success(
            chatMessageFacadeService.createChatMessage(request));
}
```

`CreateChatMessageRequest` 包含：
```java
{
    agentId: "uuid...",
    sessionId: "uuid...",
    role: "user",
    content: "今天天气怎么样？",
    metadata: null  // 用户消息没有元数据
}
```

### 第3步：Service 处理（ChatMessageFacadeServiceImpl.java）

```java
public CreateChatMessageResponse createChatMessage(CreateChatMessageRequest request) {
    // 3a. 创建并持久化消息
    ChatMessage chatMessage = doCreateChatMessage(request);
    //     → request 转 DTO → DTO 转 Entity → mapper.insert() → 返回

    // 3b. 发布事件（⭐ 核心）
    publisher.publishEvent(new ChatEvent(
            request.getAgentId(),         // Agent ID
            chatMessage.getSessionId(),   // 会话 ID
            chatMessage.getContent()      // 消息内容
    ));

    // 3c. 返回消息ID给前端
    return CreateChatMessageResponse.builder()
            .chatMessageId(chatMessage.getId())
            .build();
}
```

**注意**：这里有一个重载方法：
```java
// 用户调用（发事件）
createChatMessage(CreateChatMessageRequest) → 持久化 + 发事件

// Agent 内部调用（不发事件）
createChatMessage(ChatMessageDTO) → 只持久化

// Agent 内部调用（明确不发事件）
agentCreateChatMessage(CreateChatMessageRequest) → 只持久化
```
UserMessage 进来时触发了事件 → Agent 启动。
Agent 自己产生的 AssistantMessage / ToolResponseMessage 不发事件。

### 第4步：应用层事件 + SSE 建立（并发执行）

**`ChatMessageController` 返回 200 给前端的同时：**

```
主线程（Tomcat）:
  → 返回 ApiResponse 给前端
  → HTTP 连接释放

后台线程池（async-event-*）:
  → @EventListener 收到 ChatEvent
  → 调 JChatMindFactory.create() + JChatMind.run()
```

而此时前端收到 200 后做了什么？看 `AgentChatView.tsx`：

```typescript
// 第108-155行：建立 SSE 连接
useEffect(() => {
    if (!chatSessionId) return;

    const baseRoot = BASE_URL.replace("/api", "");
    //                         ↑ http://localhost:8080/api → http://localhost:8080
    const es = new EventSource(`${baseRoot}/sse/connect/${chatSessionId}`);

    es.addEventListener("message", (event) => {
        const message = JSON.parse(event.data) as SseMessage;
        if (message.type === "AI_GENERATED_CONTENT") {
            addMessage(message.payload.message);      // 追加消息
        } else if (message.type === "AI_PLANNING") {
            setDisplayAgentStatus(true);               // 显示规划中
            setAgentStatusText(message.payload.statusText);
        } else if (message.type === "AI_THINKING") {
            setDisplayAgentStatus(true);               // 显示思考中
        } else if (message.type === "AI_EXECUTING") {
            setDisplayAgentStatus(true);               // 显示执行中
        } else if (message.type === "AI_DONE") {
            setDisplayAgentStatus(false);              // 隐藏状态
        }
    });

    return () => es.close();  // 组件卸载时关闭连接
}, [chatSessionId]);
```

### 第5步：事件监听器（ChatEventListener.java）

```java
@Component
@AllArgsConstructor
public class ChatEventListener {

    private final JChatMindFactory jChatMindFactory;

    @Async             // ← 在后台线程池执行，不阻塞主线程
    @EventListener     // ← 监听 ChatEvent
    public void handle(ChatEvent event) {
        // 创建一个 Agent 实例处理聊天事件
        JChatMind jChatMind = jChatMindFactory.create(
                event.getAgentId(),
                event.getSessionId()
        );
        jChatMind.run();  // ← 进入 Think-Execute 循环
    }
}
```

### 第6步：Factory 构建 Agent（JChatMindFactory.java）

```java
public JChatMind create(String agentId, String chatSessionId) {
    // 6a. 从数据库加载 Agent 配置
    Agent agent = loadAgent(agentId);
    //     执行 SQL: SELECT * FROM agent WHERE id = CAST(#{agentId} AS uuid)

    // 6b. 解析配置（JSONB → DTO）
    AgentDTO agentConfig = toAgentConfig(agent);
    //     数据库存的 JSON 字符串 → 类型安全的 Java 对象
    //     "[\"databaseTool\",\"emailTool\"]" → ["databaseTool", "emailTool"]

    // 6c. 恢复聊天记忆
    List<Message> memory = loadMemory(chatSessionId);
    //     从 chat_message 表查最近 N 条 → 转为 Message 列表
    //     按 role 分别转为 UserMessage / AssistantMessage / ToolResponseMessage

    // 6d. 解析关联知识库
    List<KnowledgeBaseDTO> knowledgeBases = resolveRuntimeKnowledgeBases(agentConfig);

    // 6e. 解析可用工具（合并 FIXED + OPTIONAL）
    List<Tool> runtimeTools = resolveRuntimeTools(agentConfig);

    // 6f. 转换为 Spring AI 的 ToolCallback
    List<ToolCallback> toolCallbacks = buildToolCallbacks(runtimeTools);

    // 6g. 构造 JChatMind 实例
    return buildAgentRuntime(agent, memory, knowledgeBases, toolCallbacks, chatSessionId);
}
```

### 第7步：Agent 运行（JChatMind.run()）

见 [01-Agent核心-JChatMind.md](01-Agent核心-JChatMind.md) 的详细说明。

核心流程：
```
run() → for i=0..20:
  step():
    think():   调LLM → 有 tool_call? → 返回true/false
                                    ↓
    execute(): 执行工具 → 是否 terminate?
```

### 第8步：SSE 推送回前端

Agent 每产生一条消息（AssistantMessage 或 ToolResponseMessage）：

```
saveMessage(message)
  → 构建 ChatMessageDTO
  → chatMessageFacadeService.createChatMessage(dto)  ← 存 DB
  → pendingChatMessages.add(dto)                      ← 加入待推送队列

refreshPendingMessages()
  → 遍历 pendingChatMessages
  → 每个 message 包装为 SseMessage{type: AI_GENERATED_CONTENT}
  → sseService.send(chatSessionId, sseMessage)        ← 推送 SSE
  → pendingChatMessages.clear()
```

SSE 推送的数据结构（SseMessage.java）：
```java
{
    "type": "AI_GENERATED_CONTENT",       // 消息类型
    "payload": {
        "message": {
            "id": "uuid...",
            "sessionId": "uuid...",
            "role": "assistant",           // 或 "tool"
            "content": "今天深圳气温25°C...",
            "metadata": {
                "toolCalls": [...]         // 如果是 assistant 且有调工具
                // 或
                "toolResponse": {...}      // 如果是 tool 消息
            }
        },
        "statusText": null,
        "done": false
    },
    "metadata": {
        "chatMessageId": "uuid..."
    }
}
```

## 三、关键设计决策总结

| 决策 | 为什么 |
|------|--------|
| Controller 不直接调 Agent | 解耦，Async 不阻塞 HTTP 线程 |
| 先存消息再发事件 | 保证消息不丢 |
| Factory 构建 Agent | 封装复杂的构建逻辑（6步） |
| 滑动窗口只保留 N 条 | 防止上下文超长（Token 限制） |
| 关掉自动工具执行 | 自己控制 Think-Execute 循环 |
| 每步都持久化 + SSE | 实时展示 Agent 状态 |
| pendingMessages 批量推送 | 保证消息有序到达前端 |

## 四、SSE 连接 vs 消息创建的时间线

```
时间线 →
  │
  │  前端 POST 消息
  │  ───────────►  后端存消息、发事件
  │  ◄───────────  200 OK
  │
  │  前端收到 200 后，React useEffect 触发
  │  ───────────►  GET /sse/connect/{sessionId}
  │  ◄───────────  SSE 连接建立（EventSource）
  │
  │  同时后台线程池：
  │  ChatEventListener.handle() → JChatMind.run()
  │
  │  当 Agent 产生第一条消息：
  │  ───────────► SSE push: AI_GENERATED_CONTENT
  │  ───────────► SSE push: AI_DONE
```

**潜在问题**：如果 Agent 运行太快，在 SSE 连接建立之前就产生了消息，前端会丢失。但当前实现中，由于 `@Async` 线程池调度 + SSE 连接建立有时间差，这个概率较低。改进方案：消息先存 DB，前端刷新页面时通过 GET API 重新加载。
