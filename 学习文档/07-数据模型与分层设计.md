# 07 — 数据模型与分层设计

---

## 一、为什么分这么多层？

```
前端                           后端
 │                              │
 │  JSON (snake_case)           │
 │    ↓                         │
 │  Request (接收)              │
 │    ↓                         │
 │  DTO (业务层)                │
 │    ↓                         │
 │  Entity (数据库)             │
 │    ↓                         │
 │  DTO (业务层)                │
 │    ↓                         │
 │  VO (响应)                   │
 │    ↓                         │
 │  JSON (返回前端)              │
```

**每层的职责**：

| 层 | 类后缀 | 职责 | JSONB字段类型 |
|-----|--------|------|--------------|
| 数据库映射 | Entity | 和数据库表字段一一对应 | `String`（JSON字符串） |
| 业务传输 | DTO | 类型安全、含枚举/对象 | `List<String>` / `ChatOptions` 等 |
| 视图响应 | VO | 返回前端，只包含展示需要的字段 | 同 DTO |
| 请求入参 | Request | 前端传来的请求体 | 同 DTO |

**好处**：
1. **关注点分离**：Entity 不暴露给前端，VO 不污染数据库
2. **类型安全**：DTO 中 `List<String>` 类型明确，Entity 中是 String（JSON字符串），不用手动序列化
3. **灵活性**：前端需要的数据格式可以和数据库不一样

## 二、以 Agent 为例看完整转换链路

### Agent 表结构

```sql
CREATE TABLE agent (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name TEXT NOT NULL,
    description TEXT,
    system_prompt TEXT,
    model TEXT,                          -- "deepseek-chat"
    allowed_tools JSONB,                 -- "[\"databaseTool\",\"emailTool\"]"
    allowed_kbs JSONB,                   -- "[\"kb-uuid-1\", \"kb-uuid-2\"]"
    chat_options JSONB,                  -- "{\"temperature\":0.7,\"topP\":1.0,\"messageLength\":10}"
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);
```

### Entity（数据库映射）

```java
@Data
@Builder
public class Agent {
    private String id;
    private String name;
    private String description;
    private String systemPrompt;
    private String model;            // 数据库存字符串 "deepseek-chat"
    private String allowedTools;     // JSONB → String "[\"databaseTool\"]"
    private String allowedKbs;       // JSONB → String
    private String chatOptions;      // JSONB → String "{\"temperature\":0.7}"
    private LocalDateTime createdAt;
    private LocalDateTime updatedAt;
}
```

### DTO（业务层）

```java
@Data
@Builder
public class AgentDTO {
    private String id;
    private String name;
    private String description;
    private String systemPrompt;
    private ModelType model;            // ← 枚举类型，不是 String！
    private List<String> allowedTools;  // ← List，不是 JSON String！
    private List<String> allowedKbs;
    private ChatOptions chatOptions;    // ← 对象，不是 JSON String！
    private LocalDateTime createdAt;
    private LocalDateTime updatedAt;

    public enum ModelType {
        DEEPSEEK_CHAT("deepseek-chat"),
        GLM_4_6("glm-4.6");
    }

    @Data
    @Builder
    public static class ChatOptions {
        private Double temperature;      // 默认 0.7
        private Double topP;             // 默认 1.0
        private Integer messageLength;   // 默认 10
    }
}
```

### VO（响应给前端）

```java
@Data
@Builder
public class AgentVO {
    private String id;
    private String name;
    private String description;
    private String systemPrompt;
    private AgentDTO.ModelType model;      // ← 枚举，序列化为 "deepseek-chat"
    private List<String> allowedTools;
    private List<String> allowedKbs;
    private AgentDTO.ChatOptions chatOptions;
    // 不返回 createdAt / updatedAt（前端不需要）
}
```

### 转换过程

```java
// AgentConverter.java

// Entity → DTO（JSONB 字符串 → 类型安全对象）
public AgentDTO toDTO(Agent agent) throws JsonProcessingException {
    return AgentDTO.builder()
            .id(agent.getId())
            .name(agent.getName())
            .model(AgentDTO.ModelType.fromModelName(agent.getModel()))
            .allowedTools(objectMapper.readValue(
                    agent.getAllowedTools(), new TypeReference<>() {}))
                    // ↑ JSON 字符串 → List<String>
            .chatOptions(objectMapper.readValue(
                    agent.getChatOptions(), AgentDTO.ChatOptions.class))
                    // ↑ JSON 字符串 → ChatOptions 对象
            .build();
}

// DTO → Entity（类型安全对象 → JSON 字符串）
public Agent toEntity(AgentDTO dto) throws JsonProcessingException {
    return Agent.builder()
            .model(dto.getModel().getModelName())  // 枚举 → String
            .allowedTools(objectMapper.writeValueAsString(dto.getAllowedTools()))
            .chatOptions(objectMapper.writeValueAsString(dto.getChatOptions()))
            .build();
}

// DTO → VO
public AgentVO toVO(AgentDTO dto) {
    return AgentVO.builder()
            .id(dto.getId())
            .name(dto.getName())
            .model(dto.getModel())
            .allowedTools(dto.getAllowedTools())
            .chatOptions(dto.getChatOptions())
            .build();
}
```

## 三、JSONB 字段的序列化/反序列化

### 存储时（toEntity）

```java
// String → ObjectMapper → JSON String → DB JSONB
String json = objectMapper.writeValueAsString(dto.getAllowedTools());
// List["databaseTool", "emailTool"] → "[\"databaseTool\",\"emailTool\"]"
```

### 读取时（toDTO/selectById）

```java
// DB JSONB → CAST to text → ObjectMapper → 类型安全对象
List<String> tools = objectMapper.readValue(
        agent.getAllowedTools(), new TypeReference<List<String>>() {});
```

### MyBatis XML 中的处理

```xml
<!-- 插入时：Java String → PG JSONB -->
CAST(#{allowedTools} AS jsonb)

<!-- 查询时：PG JSONB → Java String（通过 ::text 转换） -->
allowed_tools::text AS allowed_tools
```

## 四、PgVectorTypeHandler — 自定义 TypeHandler

```java
@MappedJdbcTypes(JdbcType.OTHER)    // PG vector 类型对应 JDBC OTHER
@MappedTypes(float[].class)          // Java float[] ↔ PG vector
public class PgVectorTypeHandler extends BaseTypeHandler<float[]> {

    // 写入：float[] → "[0.1,0.2,...]" → ps.setObject
    public void setNonNullParameter(PreparedStatement ps, int i,
            float[] parameter, JdbcType jdbcType) {
        ps.setObject(i, toPgVector(parameter), Types.OTHER);
    }

    // 读取："[0.1,0.2,...]" → parse → float[]
    public float[] getNullableResult(ResultSet rs, String columnName) {
        return parse(rs.getString(columnName));
    }
}
```

**为什么需要它？** PostgreSQL 的 `vector` 类型不是标准 SQL 类型，MyBatis 不认识它。通过 TypeHandler，MyBatis 知道要把 Java 的 `float[]` 字段对应到数据库的 `VECTOR` 类型，并知道怎么读写。

### 配置注册

```yaml
mybatis:
  type-handlers-package: com.kama.jchatmind.typehandler
```

## 五、统一响应格式

### ApiResponse.java

```java
@Data
public class ApiResponse<T> {
    private int code;      // 200=成功, 500=异常
    private String message;// 提示信息
    private T data;        // 数据体

    public static <T> ApiResponse<T> success(T data) {
        return new ApiResponse<>(200, "success", data);
    }

    public static <T> ApiResponse<T> error(String message) {
        return new ApiResponse<>(500, message, null);
    }
}
```

### 异常处理

```java
@RestControllerAdvice
public class GlobalExceptionHandler {
    // 业务异常 → 返回错误信息给前端
    @ExceptionHandler(BizException.class)
    public ApiResponse<Void> handleBizException(BizException e) {
        return ApiResponse.error(e.getMessage());
    }

    // 未处理异常 → 不暴露内部信息
    @ExceptionHandler(Exception.class)
    public ApiResponse<Void> handleException(Exception e) {
        log.error("服务器内部错误", e);
        return ApiResponse.error("服务器内部错误");
    }
}
```

## 六、6 张表的完整关系

```sql
-- 1. Agent（智能体）
agent (id, name, description, system_prompt, model,
       allowed_tools[JSONB], allowed_kbs[JSONB], chat_options[JSONB])

-- 2. ChatSession（会话，属于某个 Agent）
chat_session (id, agent_id FK→agent, title, metadata[JSONB])

-- 3. ChatMessage（消息，属于某个会话）
chat_message (id, session_id FK→chat_session CASCADE,
              role, content, metadata[JSONB])

-- 4. KnowledgeBase（知识库）
knowledge_base (id, name, description, metadata[JSONB])

-- 5. Document（文档，属于某个知识库）
document (id, kb_id FK→knowledge_base CASCADE,
          filename, filetype, size, metadata[JSONB])

-- 6. ChunkBgeM3（向量切片，属于某文档的某知识库）
chunk_bge_m3 (id, kb_id FK→knowledge_base CASCADE,
              doc_id FK→document CASCADE,
              content, metadata[JSONB],
              embedding VECTOR(1024))
```

**级联删除**：删 KnowledgeBase → 级联删 Document → 级联删 ChunkBgeM3
